## Co zrobiono

- `src/sum.ts` eksportuje `sum(a: number, b: number): number` → `src/sum.ts`, import w `tests/sum.test.ts`; sprawdza `pnpm typecheck`.
- Testy obejmują liczby dodatnie, ujemne, zero i ułamki → `tests/sum.test.ts`: „dodaje liczby dodatnie”, „dodaje liczby ujemne” (także znaki mieszane), „obsługuje zero”, „dodaje ułamki z tolerancją zmiennoprzecinkową” (`toBeCloseTo`, m.in. 0.1 + 0.2 ≈ 0.3).
- Argument niebędący skończoną liczbą rzuca TypeError → `Number.isFinite` dla obu argumentów; test `it.each` dla `NaN` i `±Infinity` na pierwszej i drugiej pozycji oraz `Infinity + -Infinity`.

## Decyzje

- Który argument sprawdzać → oba (`a` i `b`), bo kryterium mówi o „argumencie”, nie o konkretnym; komunikat błędu podaje obie wartości.
- Przepełnienie (`sum(Number.MAX_VALUE, Number.MAX_VALUE)` → `Infinity`) → nie rzucamy błędu, bo kryterium dotyczy argumentów, nie wyniku; opisane w „Ryzykach”.
- Eksport z `src/index.ts` → nie dodany, bo `src/index.ts` nie jest w „Zakresie” issue (tak samo jak w T-26).
- Specyfikacji i architektury nie ma w repo (`docs/00-intake/specyfikacja.md`, `docs/04-architektura/architektura.md`), pracowałem z issue. Dodatkowo przeczytane: `src/formatPLN.ts`, `tests/formatPLN.test.ts` (wzorzec stylu), `docs/07-realizacja/T-26.md` (format raportu), `.github/PULL_REQUEST_TEMPLATE.md`, `.claude/roles/worker/settings.json` (dozwolone komendy).

## Drobne uwagi

- `src/index.ts` nie reeksportuje `sum` ani `formatPLN`; do rozważenia osobnym zadaniem przy ustalaniu publicznego API.

## Ryzyka

- Suma dwóch skończonych, bardzo dużych liczb może dać `±Infinity` bez błędu.
- Ułamki mają zwykły błąd zaokrąglenia zmiennoprzecinkowego (0.1 + 0.2 = 0.30000000000000004); udokumentowane w JSDoc.
