## Decyzje

- Wersja TypeScript → `~6.0` (6.0.3), bo typescript-eslint 8.72 wspiera `typescript <6.1.0`; TS 7.0 dawał niespełniony peer dependency.
- Wersja Node → `engines.node >=24` i Node 24 w CI, bo to aktywny LTS (kontrakt „Node LTS przez fnm”); lokalnie testowane na Node 26.13.
- Instalacja pnpm w CI → `npm install -g pnpm@<packageManager>` zamiast `pnpm/action-setup`, bo to jedna akcja zewnętrzna mniej do przypinania SHA, a wersja pnpm ma jedno źródło (`package.json`).
- Pliki spoza „Zakresu” → `src/index.ts` (test dymny i build potrzebują kodu w `src/`, kryterium „kod w src/”) oraz `tsconfig.build.json` (skrypt `build` emituje tylko `src/` do `dist/`, bez testów i konfiguracji).
- Zmiana `scripts/tests/sync-status.bats` spoza pierwotnego „Zakresu” → wykonana na polecenie orkiestratora, decyzja w `docs/decyzje.md` na `main` (2026-11-04, rozszerzenie zakresu #23). Fixture'y inline w `setup()` (heredoc) zamiast osobnych plików w `scripts/tests/fixtures/`, żeby zmiana została w jednym pliku objętym decyzją.
- Dodatkowo przeczytane źródła → `scripts/sync-status.sh` (jakie pliki i klucze frontmattera czyta), `docs/status.md` i `docs/06-zadania/index.md` z `main` (format fixture'ów), `.github/PULL_REQUEST_TEMPLATE.md`, `docs/_szablony/raport-zadania.md`, `.gitignore`, `docs/konfiguracja.md`, `.claude/roles/worker/settings.json` (sprawdzenie uprawnień), strona wydań `actions/setup-node` (SHA v7.1.0). Specyfikacji i architektury w repo nie ma (`docs/00-intake/specyfikacja.md`, `docs/04-architektura/architektura.md` nie istnieją).

## Drobne uwagi

- `scripts/check-dod.sh` i bats w CI nie zależą od Node; job `testy-skryptow` bez zmian.

## Ryzyka

- Przed rozszerzeniem zakresu `testy-skryptow` był czerwony: `sync-status.bats` testy 53 i 57, bo kopiowały żywe `docs/`, w którym orkiestrator dopisał decyzje na `main`. Poprawione fixture'ami (patrz „Co zrobiono”). Zielony job potwierdza CI, nie lokalny przebieg.
- Fixture'y odzwierciedlają obecny format `status.md` i `index.md`. Gdy `sync-status.sh` zacznie zapisywać nowy klucz frontmattera, test „bez zmian” trzeba będzie uzupełnić.
- SHA `actions/setup-node` v7.1.0 odczytane ze strony GitHub przez WebFetch, bo profil workera blokuje `gh api` i `git ls-remote`.

## Propozycje dla systemu

- Profil workera: dopuścić `git ls-remote --tags https://github.com/*` (tylko odczyt), żeby zadanie szkieletu mogło przypinać akcje GitHub po SHA bez obchodzenia przez WebFetch.
- Przenieść poprawkę `scripts/tests/sync-status.bats` (fixture'y zamiast kopii żywego `docs/`) do `sh-template-projekt`, żeby nowe projekty nie miały czerwonego CI po pierwszej decyzji orkiestratora.
- Profil workera: dopuścić `bats scripts/tests/*`, żeby worker mógł lokalnie sprawdzić testy skryptów przed pushem.
- Szablon CI: dać od razu przypięty `actions/setup-node` (zakomentowany), skoro większość projektów to Node.
