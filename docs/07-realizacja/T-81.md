# Raport T-81: Punkt wejścia pakietu: src/index.ts i exports

Issue: #81
PR: #89

## Co zrobiono

- K1 (`src/index.ts` reeksportuje `sum`, `slugify`, `formatPLN`, `parseDate`, bez `paradox`): cztery
  `export { … } from "./….js"` w `src/index.ts`. Test „eksportuje dokładnie sum, slugify, formatPLN i
  parseDate, bez paradox” w `tests/index.test.ts` porównuje `Object.keys` przestrzeni nazw z dokładną listą
  czterech nazw i sprawdza brak `paradox`.
- K2 (`package.json`: `exports` „.” na `./dist/index.js` i typy `./dist/index.d.ts`, `main` i `types`
  spójne, tylko ESM): `"exports": { ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js" } }`,
  `"main": "./dist/index.js"`, `"types": "./dist/index.d.ts"`, `"type": "module"` bez zmian; brak warunku
  `require`. Testy w bloku „package.json: exports tylko ESM (W-06)”: `type`, dokładna postać `exports`,
  `main` i `types`.
- K3 (test importuje cztery funkcje i sprawdza po jednym wywołaniu każdej): `tests/index.test.ts`
  importuje przez `../src/index.js` (wariant dopuszczony w kryterium); wywołania `sum(2, 3)` → 5,
  `slugify("Zażółć gęślą jaźń: Łódź")` → `zazolc-gesla-jazn-lodz`, `formatPLN(1234.5)` → `1 234,50 zł` z
  U+00A0, `parseDate("04.11.2026")` → `Date.UTC(2026, 10, 4)` (scenariusze O-1–O-4 planu).
- K4 (`pnpm build` tworzy `dist/index.js` i `dist/index.d.ts`; lint, typecheck, test zielone): sekcja
  „Testy”. Dodatkowo import przez nazwę pakietu (samoodwołanie przez `exports`) na zbudowanym `dist/`:
  `node --input-type=module -e "import * as p from 'sh-dryrun'; …"` wypisało
  `formatPLN,parseDate,slugify,sum 5 zazolc-gesla-jazn-lodz`.

## Testy

- `pnpm test tests/index.test.ts` przed implementacją: czerwone („Cannot find module '../src/index.js'”).
- `pnpm build` (tsc -p tsconfig.build.json): zielone; `dist/` zawiera `index.js` i `index.d.ts`.
- `pnpm lint` (eslint): zielone, bez uwag.
- `pnpm typecheck` (tsc --noEmit): zielone.
- `pnpm test` (vitest): zielone, 6 plików, 78 testów.
- Komenda testów z issue (`pnpm build`, potem `pnpm test tests/index.test.ts`): zielone, 8 testów.
- E2E: nie dotyczy (biblioteka bez UI).

## Decyzje

- Import w teście przez `"sh-dryrun"` czy `../src/index.ts`? → `../src/index.js`, bo w CI `pnpm typecheck`
  i `pnpm test` biegną przed `pnpm build` (`.github/workflows/ci.yml`), a samoodwołanie wymaga `dist/`.
  Pole `exports` sprawdza osobny test na `package.json`, a import przez nazwę pakietu sprawdzony ręcznie
  komendą `node` po buildzie (sekcja „Co zrobiono”, K4).
- Warunki w `exports` → tylko `types` i `import` (bez `require` i `default`), zgodnie z „tylko ESM” i
  „Poza zakresem: wersja CJS”.
- Dodatkowo przeczytane: `.github/workflows/ci.yml` (kolejność kroków), `docs/04-plan/plan.md` (O-1),
  `docs/07-realizacja/T-80.md` (format raportu), testy `formatPLN` i `parseDate` (oczekiwane wartości).
