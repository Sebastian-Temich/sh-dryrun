## Decyzje

- Spacja twarda czy zwykła jako separator tysięcy? → zwykła (U+0020), także przed „zł”. Wynik łatwiej porównywać i wklejać, a issue dopuszcza oba warianty pod warunkiem udokumentowania w teście.
- `Intl.NumberFormat("pl-PL")` czy własne formatowanie? → własne. Locale `pl` w ICU nie grupuje liczb czterocyfrowych (`minimumGroupingDigits` = 2), więc dałoby „1234,50 zł” zamiast wymaganego „1 234,50 zł”; do tego wynik zależałby od wersji ICU w Node i używałby twardych spacji.
- Sposób zaokrąglania → `Math.round(|kwota| * 100)`, czyli połówki od zera na wartości bezwzględnej, a potem znak. Kwota ujemna symetryczna do dodatniej.
- Ujemna kwota zaokrąglona do zera (np. -0.001, -0) → „0,00 zł” bez minusa, bo „-0,00 zł” myli czytelnika.
- Eksport z `src/index.ts` → nie dodany, bo plik jest poza „Zakresem” issue; funkcja jest dostępna z `src/formatPLN.ts`.
- Przeczytane źródła spoza „Wejścia” → `docs/07-realizacja/T-8.md` (wzór raportu), `docs/_szablony/raport-zadania.md`, `.github/PULL_REQUEST_TEMPLATE.md`, `src/index.ts`, `tests/smoke.test.ts` (konwencja importów). `docs/00-intake/specyfikacja.md` i `docs/04-architektura/architektura.md` nie istnieją w repo.

## Drobne uwagi

- `src/index.ts` nie reeksportuje `formatPLN`; publiczne API paczki (`dist/index.js`) jej nie zawiera. Warto dodać reeksport w osobnym zadaniu.

## Ryzyka

- Błędy reprezentacji liczb zmiennoprzecinkowych przy połówkach groszy: np. `1.005 * 100` = 100.49999…, więc `formatPLN(1.005)` daje „1,00 zł”, a nie „1,01 zł”. Zachowanie jak `toFixed`; kryterium nie precyzuje reguły dla takich przypadków.
- Kwoty powyżej `Number.MAX_SAFE_INTEGER / 100` (ok. 90 bilionów zł) tracą precyzję groszy; dla bardzo dużych wartości `toString()` daje zapis wykładniczy i wynik byłby błędny. Nie testowane.
- Wywołanie z JS z wartością nienumeryczną (np. string) nie jest walidowane typem; `Number.isFinite` zwróci `false` i funkcja rzuci TypeError, co jest bezpiecznym zachowaniem.
