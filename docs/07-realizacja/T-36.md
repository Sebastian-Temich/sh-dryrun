# Raport T-36: QA M1: punkt wejścia pakietu nie eksportuje funkcji biblioteki

Issue: #36
PR: #37

## Co zrobiono

- `src/index.ts` reeksportuje `sum`, `slugify`, `formatPLN` i `parseDate` (reeksport wartości niesie
  sygnatury, `dist/index.d.ts` zawiera deklaracje). Test: `tests/smoke.test.ts` („punkt wejścia
  reeksportuje funkcje biblioteki”).
- `package.json` ma `exports["."]` z `types: ./dist/index.d.ts` i `default: ./dist/index.js`. Test:
  `tests/smoke.test.ts` („package.json wskazuje dist/index.d.ts i dist/index.js w exports ".”).
- Po `pnpm build` `node -e "import('./dist/index.js').then(m=>console.log(Object.keys(m)))"` daje
  `[ 'VERSION', 'formatPLN', 'parseDate', 'slugify', 'sum' ]`.
- Import po nazwie pakietu (self-reference przez `exports`): `node -e "import('sh-dryrun')..."` z katalogu
  projektu zwraca te same klucze, `formatPLN(1234.5)` daje `1 234,50 zł`.
- `tests/qa/M1-przeplywy.test.ts`: QA-M1-1 jest zwykłym `it` (bez `it.fails`) i przechodzi.

## Testy

- Przed zmianą kodu: nowe testy i QA-M1-1 bez `it.fails` czerwone (3 niezaliczone), zgodnie z TDD.
- `pnpm lint && pnpm typecheck && pnpm test && pnpm build`: zielone, 6 plików, 77 testów, build bez błędów.
- `gitleaks git --redact --no-banner .`: brak wycieków.

## Decyzje

- Czy dodawać `main`/`types` na najwyższym poziomie `package.json`? → nie, kryterium wymaga tylko
  `exports`, a Node ≥ 24 i TypeScript z `NodeNext` czytają `exports`.
- Jak sprawdzić formatPLN w smoke teście bez znaku spacji twardej w kodzie (reguła eslint
  `no-irregular-whitespace`)? → `toMatch(/^1,00\szł$/)`, bo `\s` obejmuje spację twardą.

## Drobne uwagi

- brak

## Ryzyka

- Pakiet ma `"private": true`, więc publikacja w npm nie jest sprawdzana; import po nazwie sprawdzony
  tylko jako self-reference z katalogu projektu.
- `exports` zamyka dostęp do ścieżek głębszych (np. `sh-dryrun/dist/sum.js`); dziś nikt ich nie używa.

## Propozycje dla systemu

- Narzędzie Write/Edit zamieniało w teście sekwencję ` ` na literalny znak, co blokował eslint.
  Warto w szablonie testów zalecać `\s` zamiast ` ` w wyrażeniach regularnych.
