# Raport T-41: formatPLN(kwota) z testami

Issue: #41
PR: #46

## Co zrobiono

- `src/formatPLN.ts` eksportuje `formatPLN(kwota: number): string` → `src/formatPLN.ts`, import
  w `tests/formatPLN.test.ts`.
- `1234.5` daje „1 234,50 zł” → test „formatuje 1234.5 jako „1 234,50 zł” ze spacją twardą
  (U+00A0)”. Separatorem tysięcy i odstępem przed „zł” jest spacja twarda U+00A0, co test sprawdza
  dosłownie (`1 234,50 zł`) i dodatkowo sprawdza brak zwykłej spacji. Testy grupowania:
  „nie dodaje separatora tysięcy dla kwot poniżej 1000”, „grupuje tysiące co trzy cyfry”.
- Kwoty ujemne mają znak minus, zaokrąglenie do 2 miejsc → testy „kwoty ujemne mają znak minus”,
  „zaokrągla do 2 miejsc po przecinku, połówki od zera” (m.in. `1.005` → `1,01`, `999.995` →
  `1 000,00`, `-2.345` → `-2,35`), „nie pokazuje minusa, gdy kwota ujemna zaokrągla się do zera”.
- `NaN` i `Infinity` rzucają `TypeError` → test `rzuca TypeError dla %s` dla `NaN`, `Infinity`,
  `-Infinity`.

## Decyzje

- Spacja twarda czy zwykła jako separator tysięcy? → spacja twarda U+00A0, także przed „zł”, bo nie pozwala przełamać kwoty między wierszami; udokumentowane w komentarzu i asercjach `tests/formatPLN.test.ts`.
- `Intl.NumberFormat('pl-PL')` czy własne formatowanie? → własne, bo `pl-PL` w ICU nie grupuje liczb czterocyfrowych (daje „1234,50 zł”, wbrew kryterium), a wynik `Intl` zależy od wersji ICU w Node.
- Sposób zaokrąglania → „połówki od zera” na zapisie dziesiętnym liczby (`String(kwota)`) z arytmetyką `BigInt`, a nie `Math.round(kwota * 100)`, bo `1.005 * 100` daje `100.49999…` i wynik `1,00`. Kwoty od `1e21` (zawsze całkowite) przez `BigInt(kwota)`, kwoty poniżej `1e-6` dają `0,00 zł`.
- Znak minus → ASCII `-` (U+002D) na początku napisu; kwota ujemna zaokrąglona do zera (`-0.004`, `-0`) bez minusa, bo „-0,00 zł” nie ma sensu księgowego.
- Plik spoza „Zakresu” → `docs/07-realizacja/T-41.md` (raport wymagany przez proces). Projekt nie ma `docs/00-intake/specyfikacja.md` ani `docs/04-architektura/architektura.md`; dodatkowo przeczytane `src/index.ts`, `tests/smoke.test.ts`, `package.json`, `vitest.config.ts`, `eslint.config.js`, `docs/07-realizacja/T-38.md`, szablony raportu i PR.

## Drobne uwagi

- `formatPLN` nie jest reeksportowany z `src/index.ts` (punkt wejścia pakietu), bo plik jest poza „Zakresem”. Bez tego funkcja nie jest dostępna przez `import { formatPLN } from 'sh-dryrun'`. Do dodania osobnym zadaniem.

## Ryzyka

- Kwoty powyżej `Number.MAX_SAFE_INTEGER / 100` (ok. 90 bln zł) tracą dokładność groszy już w samej liczbie `number`; funkcja formatuje najkrótszy zapis dziesiętny tej liczby, ale nie odzyska utraconej precyzji.
- CI na PR sprawdzone po pushu (wynik w odpowiedzi dla orkiestratora).
