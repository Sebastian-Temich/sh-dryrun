# Raport T-99: formatPLN: kwota w złotych (W-02)

Issue: #99
PR: #107

## Co zrobiono

- Eksport: `export { formatPLN } from './format-pln.js';` w linii pod `// W-02 format kwoty` w
  `src/index.ts`; `src/format-pln.test.ts` importuje z `./index.js` (wszystkie testy pliku padały
  „formatPLN is not a function” przed implementacją).
- W-02/K1: test „W-02/K1: 123456 groszy daje „1 234,56 zł” ze zwykłą spacją U+0020”: wynik
  `1 234,56 zł`, znak pod indeksem 1 ma kod 0x20, w wyniku brak kodów 0xa0 i 0x202f.
- W-02/K2: test „W-02/K2: 0 groszy daje „0,00 zł””.
- W-02/K3: test „W-02/K3: -1250 groszy daje „-12,50 zł””.
- W-02/K4: testy „W-02/K4: 12.5 daje RangeError …” i „W-02/K4: NaN daje RangeError …”: klasa
  `RangeError` i komunikat „Kwota musi być całkowitą liczbą groszy”.
- W-02/K5: test „W-02/K5: Number.MAX_SAFE_INTEGER daje „90 071 992 547 409,91 zł” bez utraty cyfr”
  (także wartość ujemna).
- Przypadki brzegowe: `-0` → „0,00 zł”, kwoty poniżej złotówki (5, -99), granice tysięcy (99999,
  100000, -100000000), `Infinity`, `MAX_SAFE_INTEGER + 1` i tekst `'100'` → `RangeError`.
- Implementacja `src/format-pln.ts` bez `Intl` (karta: „Bez zależności od `Intl` w wyniku”):
  cyfry z `String(Math.abs(grosze))`, dopełnienie zerami do 3 znaków, separator tysięcy spacją U+0020.

## Decyzje

- Testy szkieletu w `src/index.test.ts` (plik spoza „Zakresu”) → po dodaniu eksportu padały oba
  („bez eksportów funkcji” i „pusta linia pod komentarzem”), więc pierwsza wersja PR je poluzowała.
  Po scaleniu #98 konflikt rozwiązany wersją z `main` (lista eksportów z planu, linia sekcji pusta
  albo eksport), która akceptuje `formatPLN`; PR nie zmienia już tego pliku.
- Zakres wejścia → `Number.isSafeInteger`, a nie `Number.isInteger`: liczby całkowite powyżej
  `MAX_SAFE_INTEGER` nie są dokładne (K5 „bez utraty cyfr”), a od 1e21 `String()` daje zapis
  wykładniczy; dostają ten sam `RangeError` co ułamek (karta: „Kwota z ułamkiem groszy albo nie
  liczba”).
- `-0` → „0,00 zł” bez minusa (warunek `grosze < 0`), zgodnie z K2 dla zera.
- Wartość niebędąca liczbą (np. tekst) w czasie wykonania → `RangeError` z tym samym komunikatem
  (karta, stan „Błąd w danych”: „albo nie liczba”), a nie `TypeError`.
- Dodatkowo przeczytane: `docs/06-zadania/zadania.yaml` (konwencja sekcji `src/index.ts`) i
  `docs/07-realizacja/T-97.md` (testy szkieletu).

## Drobne uwagi

- Komentarz w nagłówku `src/index.ts` mówi „w pustej linii pod komentarzem”, a test szkieletu z T1
  wymagał, żeby ta linia była pusta; T2 i T4–T7 trafią na ten sam problem przy swoich eksportach.

## Ryzyka

- CI na PR: wynik w odpowiedzi do orkiestratora (`gh pr checks`).

## Propozycje dla systemu

- Skill `sh-plan` / zadanie szkieletu: test szkieletu `src/index.ts` pisać od razu tak, żeby
  akceptował eksport w linii sekcji (pusta linia albo `export … from`), zamiast „bez eksportów
  funkcji”; inaczej każde zadanie funkcji musi zmieniać plik spoza swojego „Zakresu”.
- Skill `sh-tdd-testy`, punkt 8: narzędzie Write zamieniło w treści pliku ` ` w wyrażeniu
  regularnym na sam znak (ESLint `no-irregular-whitespace`), a Edit potem nie znalazł tej linii.
  Pewniejszy wzorzec: porównywać kody znaków (`charCodeAt`, `0xa0`) zamiast wpisywać escape.
