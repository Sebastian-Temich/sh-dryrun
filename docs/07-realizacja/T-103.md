# Raport T-103: przelicz: kwota w walucie obcej na grosze (W-06)

Issue: #103
PR: #108

## Co zrobiono

- Eksport z `src/index.ts` w sekcji `// W-06 przeliczenie`: linia
  `export { przelicz } from './przelicz.js';`. `src/przelicz.test.ts` importuje z `./index.js`; test
  „jest eksportowane z src/index.ts w sekcji // W-06” sprawdza tę linię. Test „src/przelicz.ts nie
  importuje src/kurs-nbp.ts” sprawdza, że `src/przelicz.ts` nie ma żadnego `import` ani odwołania do
  `kurs-nbp`. Po `pnpm build` `dist/index.js` eksportuje `[ 'przelicz' ]`.
- Kontrakt z ADR-002: `przelicz(kwota, kod, opcje?: { kurs?, zrodloKursu? }): Promise<number>`
  (grosze); `kurs` ma pierwszeństwo przed `zrodloKursu` (test „kurs podany wprost ma pierwszeństwo
  przed źródłem kursu”).
- W-06/K1: test „W-06/K1: 10 EUR po kursie 4.3 daje 4300 groszy”.
- W-06/K2: testy „W-06/K2: 1 po kursie 4.225 (dokładnie 422,5 gr) daje 423…” i „W-06/K2: 1 po kursie
  4.2249 daje 422”. Arytmetyka dziesiętna: każda liczba z najkrótszego zapisu `String(x)` zamieniana
  na mantysę `bigint` i wykładnik dziesiętny, iloczyn × 100 liczony na `bigint`, zaokrąglenie połówek
  w górę na reszcie z dzielenia (P6). Dodatkowo test „1.005 po kursie 1 to 101” (binarnie
  100.49999…) i notacja wykładnicza (`1e-7`, `1e21`).
- W-06/K3: test „W-06/K3: bez kursu bierze kurs ze źródła: 2 EUR przy atrapie 4.25 daje 850” (atrapa
  `vi.fn` dostaje kod `EUR`) i „W-06/K3: bez kursu i bez źródła daje RangeError „Brak kursu: podaj kurs
  albo źródło kursu”” (bez opcji i z `{}`).
- W-06/K4: testy „W-06/K4: kwota -1 daje RangeError…” i „W-06/K4: kurs 0 daje RangeError…” z
  komunikatem „Nieprawidłowa kwota albo kurs”.
- Stany karty: „Pusty” (kwota 0 → 0), „Błąd w danych” także dla NaN, nieskończoności, tekstu zamiast
  liczby, kursu ujemnego i kursu 0 ze źródła; „Błąd po naszej stronie” — błąd źródła kursu przechodzi
  bez zmian (test z błędem „Usługa NBP niedostępna”). Kwota ujemna jest odrzucana przed wywołaniem
  źródła kursu.

  zmianie zielone, 2 pliki, 19 testów, pokrycie 100% linii, gałęzi i funkcji.
- `pnpm lint`: zielone.
- `pnpm typecheck`: zielone.
- `pnpm build`: zielone; `node --input-type=module --eval` z importem `./dist/index.js` daje
  `[ 'przelicz' ]` i `przelicz(1, 'USD', { kurs: 4.225 })` = 423.

## Decyzje

- `src/index.test.ts` (spoza „Zakresu”, test szkieletu z T1) wymagał braku eksportów funkcji i pustej
  linii pod każdą sekcją, więc padał po dodaniu eksportu z kryterium → zmieniony identycznie jak w
  otwartym PR #106 (T-98): dopuszcza eksporty z planu i pod sekcją pustą linię albo jeden
  `export { x } from './plik.js';`. Te same hunki w obu PR-ach, więc merge drugiego nie da konfliktu
  w tym pliku.
- Kwota z ułamkiem (np. 1.005) → dopuszczona i liczona dziesiętnie; karta nie ogranicza liczby miejsc
  po przecinku kwoty ani kursu.
- „Nie liczba” z karty (stan „Błąd w danych”) → także NaN i ±Infinity dają „Nieprawidłowa kwota albo
  kurs”; kurs zwrócony przez `zrodloKursu` jest walidowany tak samo jak podany wprost.
- Kod waluty → nie jest walidowany, tylko przekazywany do `zrodloKursu`; karta ani ADR-002 nie
  definiują błędu dla kodu, a walidację kodu (tabela A NBP) ma W-05.
- Kurs w opcjach równy `undefined` → traktowany jak brak kursu (ADR-002: „`kurs` brak”).

## Ryzyka

- Bardzo duże wyniki (powyżej `Number.MAX_SAFE_INTEGER` groszy) zwracane jako `number` tracą
  dokładność; karta nie określa górnej granicy kwoty.
- `src/index.ts` i `src/index.test.ts` zmieniają też PR #106 i kolejne zadania funkcji; w `index.ts`
  każde zadanie wpisuje inną linię, więc konflikt nie powinien wystąpić, ale kolejność merge'y może
  wymagać `gh pr update-branch`.
- CI na PR niesprawdzone w chwili pisania raportu; stan w odpowiedzi dla orkiestratora.

## Propozycje dla systemu

- Jak w T-98: test szkieletu `src/index.test.ts` w zadaniu T1 powinien od razu dopuszczać eksporty z
  planu, żeby zadania funkcji uruchamiane równolegle nie zmieniały tego samego pliku spoza „Zakresu”.
