# Raport T-21: QA M1: punkt wejścia pakietu nie eksportuje funkcji biblioteki

Issue: #21
PR: #PR_NR

## Co zrobiono

- `src/index.ts` reeksportuje `sum`, `slugify`, `formatPLN` i `parseDate` (`export { … } from`),
  więc sygnatury typów przechodzą do `dist/index.d.ts`. `VERSION` zostaje. Test „punkt wejścia
  eksportuje dokładnie publiczne API” w `tests/smoke.test.ts` sprawdza listę eksportów, a test
  „funkcje z punktu wejścia działają razem” sprawdza typy wyników (adnotacje sprawdza `pnpm typecheck`).
- Po `pnpm build` `dist/index.js` eksportuje te cztery funkcje i `VERSION`: komenda z issue
  `node -e "import('./dist/index.js').then(m=>console.log(Object.keys(m)))"` daje
  `[ 'VERSION', 'formatPLN', 'parseDate', 'slugify', 'sum' ]`, a `dist/index.d.ts` zawiera reeksporty.
- Test QA-M1-1 w `tests/qa/M1-przeplywy.test.ts` jest zwykłym `it` (zdjęte `it.fails`) i przechodzi.

## Testy

- `pnpm lint` (eslint): zielone.
- `pnpm typecheck` (`tsc --noEmit`): zielone.
- `pnpm test` (`vitest run`): zielone, 6 plików, 68 testów.
- `pnpm build` (`tsc -p tsconfig.build.json`): zielone; sprawdzenie `dist/index.js` jak wyżej.
- `gitleaks git --redact --no-banner .`: brak wycieków.

## Decyzje

- Czy „z typami” wymaga osobnych `export type`? → Nie: moduły nie eksportują typów, tylko funkcje;
  `export { … } from` przenosi ich sygnatury do `dist/index.d.ts`.
- Jak sprawdzić `dist/` testem, skoro `pnpm test` biegnie przed `pnpm build`? → Testy sprawdzają
  `src/index.ts`, a `dist/` sprawdza komenda z issue po buildzie (wynik w „Co zrobiono”); test
  zależny od `dist/` byłby niestabilny bez wcześniejszego buildu.

  `src/index.ts` z dokładną listą eksportów.
