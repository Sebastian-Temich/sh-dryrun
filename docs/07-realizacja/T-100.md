# Raport T-100: chunk: dzielenie tablicy na części (W-03)

Issue: #100
PR: #109

## Co zrobiono

- Eksport z `src/index.ts` w sekcji `// W-03 dzielenie tablicy`: linia
  `export { chunk } from './chunk.js';`. `src/chunk.test.ts` importuje z `./index.js`, więc każdy test
  wchodzi od punktu wejścia. Po `pnpm build` `dist/index.d.ts` zawiera
  `declare function chunk<T>(a: readonly T[], n: number): T[][];` i `export { chunk, slugify };`.
- W-03/K1: test „W-03/K1: [1,2,3,4,5] i 2 daje [[1,2],[3,4],[5]]”.
- W-03/K2: test „W-03/K2: [] i 3 daje []”.
- W-03/K3: test parametryzowany „W-03/K3: rozmiar %s daje RangeError „Rozmiar części musi być dodatnią
  liczbą całkowitą”” dla 0, -1 i 1.5: sprawdza klasę `RangeError` i komunikat. Dodatkowo `NaN`,
  `Infinity` oraz błędny rozmiar przy pustej tablicy.
- W-03/K4: test „W-03/K4: tablica wejściowa jest niezmieniona” (wejście zamrożone `Object.freeze`,
  porównane z kopią po wywołaniu) i test „W-03/K4: sygnatura chunk<T>(a: readonly T[], n: number):
  T[][] zachowuje typ elementów” z `expectTypeOf(chunk).toEqualTypeOf<<T>(a: readonly T[], n: number)
  => T[][]>()` i `string[][]` dla `readonly string[]`; sprawdzany przez `pnpm typecheck` (tsconfig
  obejmuje `src`, w tym testy).
- Stany z karty: „Sukces” (rozmiar większy niż długość, kolejność zachowana, podział równy),
  „Częściowy sukces” (K1), „Pusty” (K2), „Błąd w danych” (K3).
- Implementacja `src/chunk.ts`: walidacja `Number.isInteger(n) && n > 0`, potem `slice` co `n`
  elementów do nowej tablicy.

## Testy

- `pnpm vitest run src/chunk.test.ts` (komenda z issue): przed implementacją 12 czerwonych
  („chunk is not a function”), po implementacji 12 zielonych.
- `pnpm test`: zielone, 3 pliki, 26 testów, pokrycie 100% linii i gałęzi.
- `pnpm lint`: zielone.
- `pnpm typecheck`: zielone.
- `pnpm build`: zielone, `dist/index.d.ts` z sygnaturą `chunk` jak w K4.

## Decyzje

- Walidacja rozmiaru przed sprawdzeniem tablicy → `chunk([], 0)` też rzuca `RangeError`, bo karta
  wiąże błąd z rozmiarem, nie z zawartością listy; spójne zachowanie niezależnie od wejścia.
- `NaN` i `Infinity` jako rozmiar → `RangeError` z tym samym komunikatem, bo nie są dodatnimi liczbami
  całkowitymi (`Number.isInteger` zwraca `false`); karta wymienia tylko 0, -1 i 1.5 jako przykłady.
- Karta W-03, P3 („Rozmiar zero albo ujemny → błąd z komunikatem”, status „do potwierdzenia”) →
  wdrożone zgodnie z proponowaną odpowiedzią, bo potwierdza ją kryterium K3 w issue.
