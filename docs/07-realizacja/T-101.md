# Raport T-101: retry: ponawianie wywołania (W-04)

Issue: #101
PR: (wpisuje shctl task close)

## Co zrobiono

- Eksport z `src/index.ts` w sekcji `// W-04 ponawianie`: `export { retry } from './retry.js';`.
  `src/retry.test.ts` importuje z `./index.js`, więc każdy test sprawdza punkt wejścia. Po
  `pnpm build` `dist/index.js` eksportuje `[ 'przelicz', 'retry', 'slugify' ]`.
- W-04/K1: test „W-04/K1: zawodzi 2 razy, potem zwraca 42: wynik 42 po 3 wywołaniach” (oraz wariant z
  domyślną przerwą na fałszywym zegarze): wynik 42, `fn` wywołana 3 razy.
- W-04/K2: test „W-04/K2: zawsze zawodzi: odrzucenie ostatnim błędem po 3 wywołaniach”: odrzucenie
  błędem „błąd 3” (ostatnim), 3 wywołania.
- W-04/K3: test „W-04/K3: przerwa 200 ms: między próbami czeka 200 i 400 ms” na `vi.useFakeTimers`:
  2. wywołanie dokładnie po 200 ms (nie po 199), 3. dokładnie po kolejnych 400 ms (nie po 399), po
  ostatniej próbie brak timera. Test „domyślnie 3 próby i przerwa 200 ms podwajana” sprawdza
  domyślne wartości z P4.
- W-04/K4: test „W-04/K4: proby 0 daje RangeError „Liczba prób musi być co najmniej 1” bez
  wywołania”: odrzucenie `RangeError` z tym komunikatem, `fn` niewywołana.
- Przypadki brzegowe: liczba prób −1, 1.5, NaN → ten sam `RangeError`; sukces za pierwszym razem bez
  przerwy (brak timera); błąd rzucony synchronicznie w `fn` też jest ponawiany.
- Implementacja `src/retry.ts`: `retry<T>(fn, { proby = 3, przerwa = 200 })`, przerwa po próbie `n`
  równa `przerwa * 2^(n-1)`, po ostatniej próbie bez czekania, odrzucenie ostatnim błędem.

## Decyzje

- K4 „then RangeError” przy funkcji asynchronicznej → `retry` zwraca odrzuconą obietnicę z
  `RangeError` (a nie rzuca synchronicznie), bo cała funkcja jest `async` i wszystkie wyniki, także
  błędy, programista obsługuje jednym `await`/`catch`.
- Liczba prób ułamkowa albo NaN (karta mówi tylko o „mniejszej niż 1”) → ten sam `RangeError`, bo
  liczba prób to liczba wywołań i musi być całkowita; komunikat bez zmian z karty.
- Błąd rzucony synchronicznie przez `fn` → traktowany jak odrzucenie i ponawiany, bo `await fn()` w
  `try` obejmuje oba przypadki, a programista nie powinien ich rozróżniać.
- Ujemna przerwa → bez walidacji (`setTimeout` traktuje ją jak 0); karta nie przewiduje błędu dla
  przerwy.
