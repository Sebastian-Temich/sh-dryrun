  `pnpm-lock.yaml`, `packageManager: pnpm@12.16.1`.
- tsconfig.json w trybie strict, kod w `src/`, testy w `tests/`: `tsconfig.json` (`strict`,
  `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `NodeNext`), kod w `src/index.ts`. Build

- vitest skonfigurowany, test dymny przechodzi: `vitest.config.ts`, `tests/smoke.test.ts` (sprawdza
  eksport `wersja` z `src/index.ts`).

  (`eslint.configs.recommended` + `tseslint.configs.strictTypeChecked`, pliki `.js` bez reguł typowanych).
- Joby lint i test w `.github/workflows/ci.yml` uruchamiają `pnpm lint`, `pnpm typecheck` (job lint)
  oraz `pnpm test` i `pnpm build` (job test) zamiast placeholderów. Pozostałe joby bez zmian.
- Tabela stacku projektu w `AGENTS.md` uzupełniona (typ, framework, instalacja, lint, testy, build,
  uruchomienie lokalne).

## Decyzje

- Wersja TypeScript → `~6.0` (6.0.3), bo typescript-eslint 8.72 ma peer `typescript <6.1.0`, a TS 7.0
  dawał niespełnioną zależność.
- Plik `src/index.ts` spoza listy „Zakres” → dodany, bo kryterium „kod w src/” i test dymny wymagają
  istniejącego modułu.
- Plik `tsconfig.build.json` spoza listy „Zakres” → dodany, bo `tsconfig.json` obejmuje też testy i
  działa z `noEmit`; osobna konfiguracja buildu emituje tylko `src/` do `dist/`.
- Instalacja pnpm w CI → `npm install -g` wersji z pola `packageManager` na Node z obrazu
  `ubuntu-24.04`, bez nowych akcji, bo repo przypina akcje po SHA, a profil workera nie pozwala
  sprawdzić SHA `actions/setup-node` ani `pnpm/action-setup`.
- Job test → uruchamia też `pnpm build`, żeby CI wykrywało zepsuty build biblioteki.
- Dodatkowo przeczytane źródło → `docs/07-realizacja/escalations/E-001.md` (eskalacja dotycząca #1 na
  `main`); worktree jest już w `/Users/Shared/sh`, więc nie blokuje zadania.

## Drobne uwagi

- `docs/00-intake/specyfikacja.md` i `docs/04-architektura/architektura.md` nie istnieją w repo

## Ryzyka

- CI na PR #7: `lint`, `test`, `check-dod`, `gitleaks` zielone; `testy-skryptow` czerwone. Padają
  testy 53 i 57 w `scripts/tests/sync-status.bats`: kopiują `docs/` projektu i zakładają pusty
  `docs/decyzje.md` oraz `docs/status.md` bez zmian, a na `main` orkiestrator już je wypełnił (m.in.
  commit E-001). PR nie zmienia tych plików ani skryptów; naprawa jest poza zakresem i w plikach
  wspólnych.
- CI korzysta z wersji Node preinstalowanej w `ubuntu-24.04`, której nie przypina repo; zmiana obrazu
  może zmienić wersję Node w CI.
